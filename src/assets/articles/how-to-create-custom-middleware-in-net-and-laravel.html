How to Create Custom Middleware in .NET and Laravel

Middleware is an essential part of modern web development. It acts as a filter for HTTP requests entering your application. Whether you want to check authentication, log user activity, or modify requests/responses, middleware has your back. In this post, I’ll show you how to create custom middleware in both .NET (ASP.NET Core) and Laravel, step-by-step.

.NET: Creating Custom Middleware

ASP.NET Core uses a pipeline to process requests. Middleware components are added to this pipeline in Startup.cs (or Program.cs in .NET 6+).

Step 1: Create the Middleware Class 


public class MyCustomMiddleware
{
    private readonly RequestDelegate _next;

    public MyCustomMiddleware(RequestDelegate next)
    {
        _next = next;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // Your custom logic here
        Console.WriteLine("Before Request");

        await _next(context);

        Console.WriteLine("After Request");
    }
}

Step 2: Register Middleware in the Pipeline

For .NET 6+, go to Program.cs and add: 

app.UseMiddleware<MyCustomMiddleware>();

If you’re using .NET 5 or below, register it inside Startup.cs: 


public void Configure(IApplicationBuilder app, IWebHostEnvironment env)
{
    app.UseMiddleware<MyCustomMiddleware>();
}

And now you have a custom middleware in the request pipeline.

Laravel: Creating Custom Middleware

Laravel makes middleware clean and expressive. Artisan even gives you a shortcut to generate one.

Step 1: Generate Middleware

Run this in the terminal: 

php artisan make:middleware MyCustomMiddleware

This creates a file at: app/Http/Middleware/MyCustomMiddleware.php

Step 2: Add Logic

Open the file and add your logic in the handle() method: 


public function handle($request, Closure $next)
{
    // Custom logic before request hits controller
    logger('Before Request');

    $response = $next($request);

    // Custom logic after controller returns response
    logger('After Request');

    return $response;
}

Step 3: Register Middleware

You can register it globally or assign it to a route.

Option 1: Global Middleware

Add it to $middleware in app/Http/Kernel.php: 


protected $middleware = [
    \App\Http\Middleware\MyCustomMiddleware::class,
];

Option 2: Route Middleware

Register it under $routeMiddleware: 


protected $routeMiddleware = [
    'mycustom' => \App\Http\Middleware\MyCustomMiddleware::class,
];

Then, use it in a route like: 


Route::get('/dashboard', function () {
    return view('dashboard');
})->middleware('mycustom');

Wrap-Up

Both .NET and Laravel give you flexibility to plug in custom logic during the request lifecycle. The concepts are similar:

Concept .NET Laravel
Middleware File InvokeAsync() in a C# class handle() in a PHP class
Register UseMiddleware() in the pipeline Global or route middleware
Use Cases Logging, Auth, CORS, etc. Logging, Auth, CORS, etc.

Knowing how to create custom middleware is super useful when building reusable, clean logic across your app. Whether you’re .NET-ing or Laravel-ing, you now know how to make it happen.
